# TaskFlow: React Native To-Do app

A full-stack Android to-do app.

| Layer | Stack |
|---|---|
| Mobile app | React Native CLI (no Expo), TypeScript, React Navigation, Axios, AsyncStorage, Context API + `useReducer` |
| API | Node.js, Express 5, Mongoose 9, JWT, bcrypt hashing, express-validator, helmet, rate limiting |
| Database | MongoDB Atlas |

Features: register / login / logout, persistent session, create / edit / delete tasks, mark complete, priority (Low / Medium / High), deadline with date and time, overdue highlighting, filter by status, pull to refresh, loading and error states, form validation on both client and server.

## 3. MongoDB Atlas setup

1. **Create a cluster.** In Atlas choose *Build a Database* → the free **M0** tier → pick a nearby region (e.g. Mumbai for India) → *Create*.
2. **Create a database user.** *Security → Database Access → Add New Database User* → authentication *Password*. Pick a username and a strong password, role **Read and write to any database**. Avoid `@ : / ? #` in the password, or URL-encode it.
3. **Allow network access.** *Security → Network Access → Add IP Address*.
   * For local development choose **Add Current IP Address**. (If your home IP changes, add it again.)
   * For a cloud-hosted API (Render, Railway, ...) you either add the host's static IP or, less strictly, `0.0.0.0/0`. Only do the latter with a strong DB password.
4. **Copy the connection string.** *Database → Connect → Drivers → Node.js*. It looks like:
   ```
   mongodb+srv://<username>:<password>@cluster0.abcde.mongodb.net/?retryWrites=true&w=majority
   ```
5. Insert your username and password, and add the database name **before the `?`**:
   ```
   mongodb+srv://myuser:mypassword@cluster0.abcde.mongodb.net/todo_app?retryWrites=true&w=majority
   ```
   Collections (`users`, `tasks`) are created automatically the first time data is saved.

## 4. Set up and run: start to finish

### 4.1 Backend

```bash
cd Backend
npm install
cp .env.example .env         # Windows PowerShell: Copy-Item .env.example .env
```

Open `Backend/.env` and set `MONGO_URI` (step 3) and `JWT_SECRET`. Generate a secret:

```bash
node -e "console.log(require('crypto').randomBytes(64).toString('hex'))"
```

Start the API:

```bash
npm run dev                   # auto-restarts on change (nodemon)
# or: npm start
```

You should see `MongoDB connected: ...` and `API running on port 5000`. Check it: open http://localhost:5000/api/health in a browser.

### 4.2 Frontend

From the **repo root** (not inside Backend):

```bash
node scripts/setup-frontend.js
```

This single command:
1. runs `npx @react-native-community/cli@latest init TodoApp --directory Frontend --skip-git-init --pm npm` to create the native project,
2. copies `App.tsx` and `src/` from this repo into it,
3. installs the extra dependencies (Axios, React Navigation, screens, safe-area-context, AsyncStorage, date-time picker),
4. adds the `onCreate(null)` tweak that `react-native-screens` recommends to `MainActivity.kt`.

**Prefer to do it by hand?** These are the equivalent commands:

```bash
mv Frontend Frontend-src                       # PowerShell: Rename-Item Frontend Frontend-src
npx @react-native-community/cli@latest init TodoApp --directory Frontend --skip-git-init --pm npm
cp -r Frontend-src/src Frontend-src/App.tsx Frontend/   # PowerShell: Copy-Item -Recurse -Force Frontend-src\src,Frontend-src\App.tsx Frontend\
rm -rf Frontend-src                            # PowerShell: Remove-Item -Recurse -Force Frontend-src
cd Frontend
npm install axios @react-navigation/native @react-navigation/native-stack \
  react-native-screens react-native-safe-area-context \
  @react-native-async-storage/async-storage @react-native-community/datetimepicker
```

### 4.3 Point the app at your API

Edit `Frontend/src/utils/constants.ts`:

| Where the app runs | `DEV_API_URL` |
|---|---|
| Android **emulator** (default) | `http://10.0.2.2:5000/api` |
| **Physical phone over USB** | run `adb reverse tcp:5000 tcp:5000`, then `http://localhost:5000/api` |
| **Physical phone on Wi-Fi** | `http://<your-computer-LAN-IP>:5000/api` (same network, and allow port 5000 through your firewall) |

`10.0.2.2` is the emulator's built-in alias for your computer's `localhost`.

### 4.4 Run the app

Start an emulator in Android Studio (or plug in a phone), then:

```bash
cd Frontend
npm start            # terminal 1: Metro bundler
npm run android      # terminal 2: builds and installs the app (first build takes several minutes)
```

Register an account, add a task, force-close and reopen the app: you stay signed in.

## 5. Environment variables

**Backend (`Backend/.env`)**

| Variable | Purpose |
|---|---|
| `PORT` | Port the API listens on (default `5000`) |
| `NODE_ENV` | `development` or `production` (production hides stack traces and request logs) |
| `MONGO_URI` | Atlas connection string, see section 3 |
| `JWT_SECRET` | Long random string that signs tokens. Keep it secret; changing it logs everyone out |
| `JWT_EXPIRES_IN` | Token lifetime, e.g. `7d` |
| `CORS_ORIGIN` | Allowed web origin. Native apps ignore CORS, so `*` is fine for a mobile-only API |

**Frontend.** React Native does not read `.env` files out of the box. The API URL lives in `src/utils/constants.ts` and switches on `__DEV__` (development vs release builds). If you later need per-environment config, add `react-native-config`.

## 6. JWT setup: how authentication works

1. `POST /api/auth/register` or `/login` verifies the input, then the API signs a JWT containing only the user id (`config/jwt.js`) and returns `{ token, user }`.
2. The app stores `token` and `user` in AsyncStorage (`utils/storage.ts`) and in `AuthContext`.
3. An Axios **request interceptor** (`services/api.ts`) adds `Authorization: Bearer <token>` to every request.
4. On the server, `middleware/auth.js` verifies the signature and expiry, loads the user, and sets `req.user`. Every task query filters by `req.user._id`, so users can only ever see and change their own tasks.
5. Passwords are hashed with bcrypt (cost 12) in the `User` model's pre-save hook, and the `password` field is `select: false`, so it is never returned by accident.
6. **Session persistence:** on launch `AuthContext` reads AsyncStorage. While it does, a spinner shows (no flash of the login screen). If a token exists, the app opens straight to the task list.
7. **Expiry:** if any protected request returns 401, an Axios **response interceptor** clears the session and the navigator returns to the login screen.
8. **Logout:** clears AsyncStorage and context. `TaskProvider` unmounts too, so the next user never sees old tasks.

> The backend uses `bcryptjs` (pure JavaScript, same algorithm and hash format as `bcrypt`). It avoids native compile problems on Windows and CI. Swapping to `bcrypt` is a one-line import change.

## 7. API reference

Base URL: `http://localhost:5000/api`. Errors always look like `{ "message": "..." }`.

| Method | Endpoint | Auth | Body | Success |
|---|---|---|---|---|
| POST | `/auth/register` | no | `{ email, password }` | `201 { token, user }` |
| POST | `/auth/login` | no | `{ email, password }` | `200 { token, user }` |
| POST | `/tasks` | yes | `{ title, description?, deadline, priority? }` | `201 { task }` |
| GET | `/tasks` | yes | (optional `?status=Pending&priority=High`) | `200 { count, tasks }` |
| PUT | `/tasks/:id` | yes | any of `title, description, deadline, priority, status` | `200 { task }` |
| DELETE | `/tasks/:id` | yes | | `200 { message, id }` |
| PATCH | `/tasks/:id/complete` | yes | | `200 { task }` |

Status codes: `400` validation, `401` missing/invalid token or bad credentials, `404` task not found (or belongs to someone else), `409` email already registered, `429` too many auth attempts.

Try it with curl:

```bash
# register and capture the token
curl -s -X POST http://localhost:5000/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{"email":"me@example.com","password":"secret123"}'

# create a task (replace TOKEN)
curl -s -X POST http://localhost:5000/api/tasks \
  -H "Authorization: Bearer TOKEN" -H "Content-Type: application/json" \
  -d '{"title":"Buy milk","deadline":"2026-12-31T18:00:00.000Z","priority":"High"}'

# list, then complete
curl -s http://localhost:5000/api/tasks -H "Authorization: Bearer TOKEN"
curl -s -X PATCH http://localhost:5000/api/tasks/TASK_ID/complete -H "Authorization: Bearer TOKEN"
```

## 8. State management: why Context API + `useReducer`

* The app has two small pieces of shared state: **who is logged in** and **the list of tasks**. Context covers both with no extra dependency.
* `useReducer` gives Redux-style predictable transitions (`FETCH_SUCCESS`, `ADD`, `UPDATE`, `REMOVE`) in a few dozen lines, without store, slice, or middleware setup.
* Contexts are split by concern (`AuthContext`, `TaskContext`) so an auth change does not re-render unrelated consumers, and values are memoised with `useMemo` / `useCallback`.
* `TaskProvider` only mounts inside the authenticated branch of `RootNavigator`, which resets task state on logout for free.
* **When to move to Redux Toolkit / RTK Query:** if you add offline sync, many entity types, cross-screen caching or optimistic updates with rollback. The service layer (`services/`) is already isolated, so only `context/` would change.

## 9. Design notes

* Priority is shown twice on purpose: a coloured **edge stripe** (scannable while scrolling) and a **badge** (readable without relying on colour alone).
* Pending tasks sort by soonest deadline; completed ones move below. Overdue pending tasks show the deadline in red.
* Error copy says what happened and what to do next; empty states point to the next action.

## 10. Production checklist

* Deploy the API (Render, Railway, Fly.io, ...) with the environment variables above, and set `NODE_ENV=production`.
* Serve it over **HTTPS**, then set `PROD_API_URL` in `constants.ts`. Release builds block plain-HTTP traffic by default; only debug builds allow it.
* Atlas: restrict Network Access, use a dedicated least-privilege DB user, keep backups on for paid tiers.
* Sign the release build with your own keystore: https://reactnative.dev/docs/signed-apk-android, then `cd Frontend/android && ./gradlew assembleRelease` (Windows: `gradlew.bat assembleRelease`).
* For higher security than AsyncStorage offers, store the token with `react-native-keychain` (only `utils/storage.ts` changes).
* Ideas for later: refresh tokens, password reset by email, push reminders before a deadline, unit tests (Jest + Supertest on the backend, React Native Testing Library on the app).

## 12. Troubleshooting

| Symptom | Fix |
|---|---|
| `MongoDB connection error: ... IP that isn't whitelisted` | Add your current IP under Atlas *Network Access* |
| `bad auth` / `Authentication failed` | Wrong DB username or password in `MONGO_URI`; URL-encode special characters |
| App shows "Cannot reach the server" on the emulator | API not running, or `DEV_API_URL` is not `http://10.0.2.2:5000/api` |
| Same message on a real phone | Use `adb reverse tcp:5000 tcp:5000` + `localhost`, or your LAN IP with the firewall open |
| `Missing required environment variable` | `.env` is missing or not in `Backend/` |
| Build fails with `SDK location not found` | Set `ANDROID_HOME`, or create `Frontend/android/local.properties` with `sdk.dir=<path to Android SDK>` |
| Metro shows stale code | `npm start -- --reset-cache` |
| Gradle problems after changing dependencies | `cd Frontend/android && ./gradlew clean`, then `npm run android` |
| `429 Too many attempts` | Auth routes are rate limited (50 per 15 minutes per IP). Wait, or raise `limit` in `Backend/app.js` |
